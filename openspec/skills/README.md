# OpenSpec Skills

`openspec/skills/` is the **canonical home** for all OpenSpec skill files. Per-environment adapter files (`.claude/commands/`, `.github/copilot-instructions/`, IntelliJ run configs) are **generated output** — regenerated by running `openspec install skills`.

## Directory Layout

```
openspec/skills/
├── README.md                  ← this file
├── <name>/
│   └── SKILL.md               ← canonical skill content + frontmatter
└── ...
```

One subdirectory per skill, named with the skill's kebab-case identifier.

## SKILL.md Frontmatter Schema

Every `SKILL.md` must begin with a YAML frontmatter block:

```yaml
---
name: propose                              # required — kebab-case identifier
description: "Propose a new change"        # required — one-line description
triggers:                                  # required — list of invocation triggers
  - /opsx:propose
agents: [claude, copilot, intellij]        # required — list of compatible targets
args: "[change-name-or-description]"       # optional — describes accepted arguments
version: "1.0.0"                           # optional — semver string
---
```

### Required Fields

| Field | Type | Description |
|---|---|---|
| `name` | string | Kebab-case identifier matching the directory name |
| `description` | string | One-line human-readable description |
| `triggers` | list of strings | Slash-command patterns (e.g., `/opsx:propose`) |
| `agents` | list of strings | Supported targets: `claude`, `copilot`, `intellij` |

### Optional Fields

| Field | Type | Description |
|---|---|---|
| `args` | string | Human-readable description of accepted arguments |
| `version` | string | Semver version of this skill |

### Validation Rules

- All four required fields must be present; a skill with any missing required field will be skipped by `openspec install skills` with an error.
- `agents` values must be drawn from: `claude`, `copilot`, `intellij`. Unknown values produce a warning.
- `name` must match the skill's directory name exactly.
- The frontmatter block must be valid YAML.

## Prose Body

Everything after the closing `---` of the frontmatter is the prose body. The prose body:

- **Is the canonical skill content** — adapter files are derived from it
- **Should use agent-agnostic language** (e.g., "read the file at `<path>`" rather than tool-specific calls)
- **May include optional hints** for specific agents using HTML comments:
  ```markdown
  <!-- Claude: use the Read tool -->
  ```
  Other agents ignore such hints.

## Installing Adapters

After adding or modifying skills, regenerate adapter files:

```bash
# All environments
openspec install skills

# Specific environment
openspec install skills --env claude
openspec install skills --env copilot
openspec install skills --env intellij
```

Adapter output paths:

| Environment | Output path |
|---|---|
| Claude | `.claude/commands/opsx/<name>.md` |
| Copilot | `.github/copilot-instructions/<name>.md` |
| IntelliJ | `.idea/runConfigurations/opsx_<name>.xml` |

## Adding a New Skill

1. Create `openspec/skills/<name>/SKILL.md` with required frontmatter
2. Write the skill's prose body instructions
3. Run `openspec install skills` to generate adapter files
4. Commit `openspec/skills/<name>/SKILL.md` — adapter files are generated output

## Migrating Existing Claude Commands

If you have existing `.claude/commands/opsx/*.md` files:

```bash
openspec migrate skills
```

This reads each `.claude/commands/opsx/<name>.md`, creates the corresponding `openspec/skills/<name>/SKILL.md` with generated frontmatter, then runs `openspec install skills --env all` automatically.
