# OpenSpec Skills

`openspec/skills/` is the **canonical home** for all OpenSpec skill files. Per-environment adapter files (`.claude/commands/`, `.github/copilot-instructions/`, IntelliJ run configs) are derived from these sources — do not edit adapter files directly.

## Directory Layout

```
openspec/skills/
├── README.md                  ← this file
├── <name>/
│   └── SKILL.md               ← canonical skill content + frontmatter
└── ...
```

One subdirectory per skill, named with the skill's kebab-case identifier.

## SKILL.md Frontmatter Schema

Every `SKILL.md` must begin with a YAML frontmatter block:

```yaml
---
name: propose                              # required — kebab-case identifier
description: "Propose a new change"        # required — one-line description (Copilot-compatible)
agent: agent                               # required — Copilot execution mode: ask | agent | plan
triggers:                                  # required — list of invocation triggers
  - /opsx:propose
agents: [claude, copilot, intellij]        # required — list of compatible targets
args: "[change-name-or-description]"       # optional — describes accepted arguments
version: "1.0.0"                           # optional — semver string
---
```

### Required Fields

| Field | Type | Description |
|---|---|---|
| `name` | string | Kebab-case identifier matching the directory name |
| `description` | string | One-line human-readable description — also used as the Copilot prompt description |
| `agent` | string | Copilot execution mode: `ask` (conversational), `agent` (file operations), `plan` (plan-first) |
| `triggers` | list of strings | Slash-command patterns (e.g., `/opsx:propose`) |
| `agents` | list of strings | Supported targets: `claude`, `copilot`, `intellij` |

### Optional Fields

| Field | Type | Description |
|---|---|---|
| `args` | string | Human-readable description of accepted arguments |
| `version` | string | Semver version of this skill |

### Copilot Compatibility

The `description` and `agent` fields match the GitHub Copilot prompt file schema (`description` required, `agent` optional). This means SKILL.md files are a superset of the Copilot prompt format — adapter files for Copilot are generated by copying `description` and `agent` into the frontmatter of `.github/copilot-instructions/<name>.md`.

Use `agent: agent` for skills that read or write files (apply, propose, archive, domain). Use `agent: ask` for conversational skills that don't modify files (explore).

### Validation Rules

- All five required fields must be present.
- `agent` must be one of: `ask`, `agent`, `plan`.
- `agents` values must be drawn from: `claude`, `copilot`, `intellij`.
- `name` must match the skill's directory name exactly.
- The frontmatter block must be valid YAML.

## Prose Body

Everything after the closing `---` of the frontmatter is the prose body. The prose body:

- **Is the canonical skill content** — adapter files are derived from it
- **Should use agent-agnostic language** (e.g., "read the file at `<path>`" rather than tool-specific calls)
- **May include optional hints** for specific agents using HTML comments:
  ```markdown
  <!-- Claude: use the Read tool -->
  ```
  Other agents ignore such hints.

## Installing Skills

Skill adapter files are written to `.claude/commands/opsx/` by `/opsx:domain init`. They are gitignored and regenerated on demand — do not commit them.

To install or reinstall skills manually, run `/opsx:domain init` or ask the domain skill to re-run its skills configuration step.

## Adding a New Skill

1. Create `openspec/skills/<name>/SKILL.md` with required frontmatter
2. Write the skill's prose body instructions
3. Commit the `openspec/skills/<name>/SKILL.md` file
4. Run `/opsx:domain init` (or ask the domain skill to configure skills) to write the adapter file

## Updating a Skill

1. Edit `openspec/skills/<name>/SKILL.md`
2. Commit the change
3. Re-run the domain skill's configure step to update `.claude/commands/opsx/<name>.md`
